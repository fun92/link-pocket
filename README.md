# Link Pocket

일반 링크와 암호화된 비밀 링크를 함께 관리하는 작은 웹앱입니다. 이메일 인증 코드를 통한 비밀번호 복구를 지원합니다.

## Netlify 배포

이 프로젝트는 Netlify 정적 호스팅, Functions, Blobs에 맞게 구성되어 있습니다.

1. 이 프로젝트를 GitHub 저장소에 올립니다.
2. Netlify에서 `Add new project` → `Import an existing project` → `GitHub`를 선택합니다.
3. 해당 저장소를 선택합니다. `netlify.toml`이 배포 설정을 자동 적용하므로 빌드 명령과 배포 폴더를 직접 입력하지 않아도 됩니다.
4. `Project configuration` → `Environment variables`에서 다음 값을 추가합니다.
   - `APP_SECRET`: 32자 이상의 긴 임의 문자열. 한 번 정한 뒤 변경하면 기존 비밀 링크를 열 수 없습니다.
   - `RESEND_API_KEY`: 실제 복구 메일을 사용할 때만 추가합니다.
   - `EMAIL_FROM`: 예: `Link Pocket <noreply@인증한도메인>`
5. `Deploy project`를 누릅니다.

`APP_SECRET`은 필수입니다. Netlify가 제공하는 `https://프로젝트이름.netlify.app` 주소가 iPhone 설치 주소입니다. Blobs 데이터는 새 버전을 배포해도 유지됩니다.

주의: Netlify 운영 환경에서는 보안을 위해 화면에 개발용 복구 코드를 표시하지 않습니다. 따라서 Resend를 설정하기 전에는 비밀번호를 잊어버렸을 때 복구할 수 없습니다.

## 실행

Node.js 20 이상에서 다음 명령을 실행하세요.

```bash
npm start
```

브라우저에서 `http://localhost:4173`을 엽니다. 별도 패키지 설치는 필요하지 않습니다.

## 아이폰 홈 화면에 설치

실제 배포된 HTTPS 주소를 iPhone Safari에서 연 다음 아래 순서로 설치합니다.

1. Safari의 `공유` 버튼을 누릅니다.
2. `홈 화면에 추가`를 선택합니다.
3. 오른쪽 위 `추가`를 누릅니다.

Link Pocket 아이콘이 홈 화면에 생기며 전체 화면 앱처럼 실행됩니다. 앱 화면의 `설치 방법`에서도 같은 안내를 볼 수 있습니다.

## 아이폰에서 링크 빠르게 담기

- 링크를 복사하고 Link Pocket을 연 뒤 `붙여넣기`를 누릅니다.
- iOS 단축어에서는 공유받은 URL을 `https://배포주소/?url=단축어입력` 형태로 열도록 구성할 수 있습니다. 앱이 열리면 링크 입력창이 자동으로 채워집니다.
- 쿼리 문자열은 입력창에 옮긴 직후 주소창 기록에서 제거합니다.

화면 뼈대는 오프라인에서도 열리지만, 로그인·링크 조회·저장은 서버 연결이 필요합니다.

## 이메일 복구 설정

개발 중에는 메일 설정이 없을 경우 인증 코드가 화면에 표시됩니다. 실제 배포에서는 다음 환경 변수를 설정하세요.

- `APP_SECRET`: 32자 이상의 임의 문자열. 변경하면 기존 비밀 링크를 열 수 없으므로 안전하게 보관합니다.
- `RESEND_API_KEY`: Resend에서 발급한 API 키
- `EMAIL_FROM`: Resend에서 인증한 발신 주소
- `NODE_ENV=production`: 운영 환경에서는 인증 코드를 화면에 노출하지 않습니다.

`.env.example`은 설정 항목 참고용이며, 이 앱은 `.env` 파일을 자동으로 읽지 않습니다. 호스팅 서비스의 환경 변수 설정 화면을 사용하거나 실행 전에 환경 변수를 주입하세요.

## 보안 구조

- 비밀번호는 scrypt 해시로 저장합니다.
- 비밀 링크의 주소·제목·메모·태그는 AES-256-GCM으로 암호화합니다.
- 비밀공간을 열 때 비밀번호를 다시 확인하고, 서버가 발급한 별도의 3분짜리 잠금 해제 토큰이 있어야만 암호문을 복호화합니다.
- 복구 코드는 10분 후 만료되고 최대 5회만 확인할 수 있습니다.
- 이메일 복구가 가능한 대신, 서버의 `APP_SECRET`을 관리하는 운영자는 기술적으로 비밀 링크를 복호화할 수 있습니다. 운영자도 볼 수 없는 종단간 암호화를 원한다면 복구키 방식으로 별도 설계해야 합니다.

## 현재 범위

첫 버전은 1대의 서버에서 소규모로 사용하는 용도입니다. iPhone 설치에는 HTTPS 배포가 필요합니다. 정식 공개 서비스 전에는 데이터베이스, 요청 속도 제한, 쿠키 기반 세션, CSRF 방어, 백업 정책을 추가해야 합니다.
